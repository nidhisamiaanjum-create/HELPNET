Project Setup from Zero

Exact Commands

Start from an empty folder and an empty GitHub repository.

# 1. Create project folder
mkdir HELPNET
cd HELPNET

# 2. Open in VS Code
code .

# 3. Initialize Git
git init

# 4. Create GitHub repo (via browser) then connect
git remote add origin https://github.com/your-org/HELPNET.git

# 5. Create main branch and push
git checkout -b main
git add .
git commit -m "chore: initial project structure"
git push -u origin main

# 6. Create develop branch
git checkout -b develop
git push -u origin develop

# 7. Create frontend (React + Tailwind)
npx create-react-app frontend --template tailwindcss
cd frontend
npm install axios react-router-dom
cd ..

# 8. Create backend (Node + Express)
mkdir backend && cd backend
npm init -y
npm install express cors dotenv bcrypt jsonwebtoken nodemailer multer cloudinary
npm install pg sequelize  # or raw pg
npm install -D nodemon
cd ..

# 9. Create .env files
touch backend/.env backend/.env.example
touch frontend/.env

# 10. Create .gitignore
echo "node_modules/\n.env\n.DS_Store\nbuild/\ndist/" > .gitignore

# 11. Create README.md
echo "# HELPNET – Unified Community Services Platform" > README.md

# 12. Initial folder structure (see below)
mkdir -p backend/src/{config,controllers,middleware,models,routes,services,utils}
mkdir -p frontend/src/{components,pages,layouts,services,hooks,context,utils}
mkdir -p database docs tests .github/workflows

After these steps, push the initial structure:

git add .
                    git commit -m "chore: initial project scaffold"
                    git push origin develop

5‑Member Git Workflow

Branch Strategy

  • main – production-ready code (protected)
  • develop – integration branch (all features merge here)
  • feature/* – one branch per task (e.g. feature/auth-register, feature/nid-verification)

Before starting work

git checkout develop
                    git pull origin develop
                    git checkout -b feature/your-task-name

During work

git status
                    git add .
                    git commit -m "feat(scope): description"

Push & PR

git push origin feature/your-task-name

Open a Pull Request from feature/your-task-name → develop. At least one reviewer (another team member) must approve.

✔ Who reviews? The team lead or a member who is not working on the same feature. Rotate reviewers to share knowledge.

Preventing Conflicts

  • Ownership: Assign specific files/features to each member (see team table).
  • Shared files: routes/index.js, package.json – coordinate via daily stand-up.
  • DB schema: One person (e.g. Samia) owns all migration files.
  • React components: Build isolated components; share via components/common/.
  • .env: Never commit; use .env.example as source of truth.
If two people must edit the same file:
1. Both pull latest develop before starting.
2. The first to merge resolves any conflicts with the second via a quick sync.

Sprint 1 – Authentication 3 tasks

Task: Register

Database

  • Table users
  • Fields: id, phone, password_hash, role, full_name, created_at, updated_at
  • Constraint: phone UNIQUE

Backend

  • Model: models/User.js
  • Controller: controllers/auth.js – register()
  • Route: POST /api/auth/register
  • bcrypt hashing, validation (phone, password strength)

Frontend

  • Page: pages/Register.jsx
  • Form with phone, password, full_name, role
  • Client validation (phone format, password length)
  • API service: services/auth.js

Testing

  • ✔ Valid registration → 201
  • ✔ Duplicate phone → 409
  • ✔ Weak password → 400
  • ✔ Missing fields → 400
Git: feature/auth-register  |  Commit: feat(auth): add user registration API and page  |  PR → develop

Task: Login & JWT

Database

  • Same users table (check password_hash)

Backend

  • Controller: login() – verify password, issue JWT
  • Route: POST /api/auth/login
  • Middleware: middleware/auth.js (verify token)

Frontend

  • Page: pages/Login.jsx
  • Store token in localStorage or context
  • Redirect to dashboard after login

Testing

  • ✔ Correct credentials → 200 + token
  • ✔ Wrong password → 401
  • ✔ Non-existent user → 404
Git: feature/auth-login  |  Commit: feat(auth): implement login and JWT flow

Task: Role & Protected Routes

Backend

  • Middleware: roleGuard(roles) – check req.user.role
  • Apply to protected endpoints

Frontend

  • Context: context/AuthContext.jsx
  • Component: components/ProtectedRoute.jsx
  • Component: components/RoleGuard.jsx

Testing

  • ✔ Unauthenticated → redirected to login
  • ✔ Wrong role → 403
Git: feature/auth-roles  |  Commit: feat(auth): add role-based guards and protected routes
